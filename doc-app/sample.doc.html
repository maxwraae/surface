A note about what files want to be.

Web applications broke this arrangement. They moved the file off the disk and into someone else's cloud. The trade was real — collaboration, ubiquity, no installs — but the cost was sovereignty. You no longer hold the artifact. You hold a permission to view it.

The opening

A new arrangement is becoming possible. Browsers can now reach the disk again, by permission. Local agents can read and write files on your behalf. The substrate can be a folder of HTML files, sitting where you put them, opened by any web app that knows the file system protocol.

This document is an example. It is an html file. It renders in any browser. You are looking at it through a small editor that knows how to open files, edit them, and save the result back to disk in real time. The editor is incidental — replace it with another and the document is unchanged. The file is the truth.

What changes when the file is the substrate

  • The work moves with you. Copy the folder, you have everything.
  • Many apps can read the same file. Different views, one source.
  • AI agents can edit alongside you. The file is the channel; the editor is just a window onto it.
  • No login. No sync. No service to outlive.
The simplest interfaces are the ones that move least information through the smallest set of well-named primitives.

Try it

Click into this paragraph and start typing. The text you write goes to disk within a few hundred milliseconds. Open this same file in a terminal — cat sample.doc.html — and you'll see your edits. Edit it in your favorite text editor; this view will update.

That is the loop. Small enough to understand. Strong enough to build on.
